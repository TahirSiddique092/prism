Chapter 12: Query Processing & Optimization

Silberschatz, Korth, Sudarshan • Database System Concepts (Sixth Edition)

12.4 Evaluation of Expressions

In the earlier sections of this chapter, we considered how individual relational operations can be executed efficiently. We now turn our attention to the evaluation of an entire relational algebra expression consisting of multiple operations.

An expression can be evaluated using either of two methods: materialization or pipelining. In materialized evaluation, the output of each operation in an expression is evaluated and stored in a temporary relation on disk, which is then used as input to subsequent operations.

Relational Join Cost Formula:
Cost(Nested_Loop) = B(r) + (N(r) * B(s)) / (M - 1)
Cost(Hash_Join) = 3 * (B(r) + B(s)) + 4 * N_buckets

In relational query processing, the optimizer evaluates multiple alternative evaluation plans for a given expression. For relational joins, the cost difference between an unindexed nested-loop join and a hash-join or merge-join can be several orders of magnitude. The query execution plan specifies exactly which join algorithm to execute for each intermediate relation.

Catalog information such as relation cardinalities, index structures, number of distinct values for attributes, and distribution histograms are referenced by the cost estimation formulas. The plan with the lowest estimated total disk I/O and CPU computational cost is selected for pipelined execution.
