Capabilities

Everything you need to interrogate a document library

Built as a DBMS project, so each capability is a database doing what it's best at — together, not in isolation.

Semantic search

Query by meaning, not keywords. Sentence embeddings (all-MiniLM-L6-v2) matched by cosine distance in pgvector surface the right passage even with zero shared words.

FULLTEXT fallback

When nothing is semantically close enough, PRISM falls back to MySQL FULLTEXT so an exact phrase still finds its home.

Topic graph

Every upload is woven into a Neo4j graph of topics, so you can jump to related documents by what they're actually about.

Inline PDF reader

Open any result and read the original PDF right in the browser, with its topics and related documents alongside.

Search analytics

See your search history, which documents surface most, and what you've uploaded but never searched.

Redis cache

Repeat a query and it returns instantly from Redis — with a "cached" badge — and invalidates cleanly when you add new documents.

Under the hood

Five datastores, one search box

A deliberate polyglot-persistence design — each store chosen for what it does best, orchestrated by a Flask API behind a Next.js UI.

Try it

Clone it. One command. Done.

No accounts, no API keys, no cloud. You need Docker and about 4–6 GB of free RAM. The whole stack comes up together.

bash
$ git clone https://github.com/TahirSiddique092/prism.git
$ cd prism
$ docker compose up

then open http://localhost:3000 → register → upload a PDF → search.

Upload

Your PDF lands in MinIO; text is chunked into MySQL, embedded into pgvector, and its topics written to Neo4j.

Search

Your question is embedded and matched by cosine distance — with FULLTEXT fallback and Redis caching.

Explore

Read the source inline, hop to related documents through the topic graph, and review your search analytics.
